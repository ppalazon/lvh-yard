# Windows 11 Workstation: aggregate acceptance evidence

This file collects what was observed for ticket 10. It makes no support claim. The maintainer reviews it, and the
[maintainer checklist](10-maintainer-checklist.md) lists what stays open.

One integrated pass ran on real Windows 11 as the ordinary account `yarddev`. It installed the packaged CLI, set up a
Workstation, started it with direct Docker Compose, published Services, joined a Linux Workstation, turned on TLS,
restarted the setup and exported a Backup. The details are in [the journey](#the-installed-product-journey). The
earlier tickets keep the detailed proof of each behavior. This file links to them and does not repeat them.

Raw output of this pass stays outside the repository in `~/.local/state/lvh-yard-windows-11/evidence/10-*.out`. The
scripts that produced it are `~/.local/state/lvh-yard-windows-11/bin/10-*`. Every quoted result below comes from
those files.

The second run, with HTTPS on and Consul TLS off, gave the same result, so the HTTPS port `49704` was closed to the
LAN while it listened on Windows loopback.

Control that failed first: a PowerShell `TcpListener` on `0.0.0.0` (ports `49711` and `49712`, explicit IPv4) was not
reachable from the Linux host (`no connection`, and the Linux Traefik request for `lan10` returned `HTTP=000` six
times; `10-j5-linux-side-run1.out`). `netstat` showed the listener on `0.0.0.0`; I did not read the owner process (the
process list was gone when I looked), so I take it to be my job's PowerShell process [inference]. I did not query the
firewall rules. The notes record only the Docker backend Allow rules, so the likely cause is that no rule allows
that process [inference, not confirmed]. I did not change the firewall. I moved the Yard target and the control into
host-network containers, and those passed. A native process that must reach other Workstations may therefore need the
user to allow it in Windows Firewall. Ticket 05 used a container for the same reason. I did not find this case in the
user guide (open item).

Source: `10-j5-linux-side.out`, `10-j5-lan-probe-rerun.out`, `10-j6c-lan-probe-https-on.out`.
